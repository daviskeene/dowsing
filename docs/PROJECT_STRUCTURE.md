# Project structure

DOWSING has three layers:

1. the runnable reference implementation
2. the generated experiment artifacts
3. the fill-in learning lab

The root repo intentionally keeps the nanoGPT entrypoints (`train.py`, `model.py`, `configurator.py`, `sample.py`) at the top level because nanoGPT expects that layout. Most DOWSING-specific code lives in `src/`, `scripts/`, `data/uncertainty_byte/`, and `lab/`.

## Top-level files

```text
README.md        project overview and motivation
LAB.md           practical lab guide for running DOWSING
SPEC.md          concise experiment specification
Makefile         common local commands
requirements.txt Python dependencies
modal_run.py     Modal GPU pipeline
pyproject.toml   lint configuration
```

`CONTEXT.md`, when present locally, is agent handoff scratch space and is ignored by git.

## nanoGPT substrate

```text
model.py
train.py
configurator.py
sample.py
```

These are the core nanoGPT files. They are intentionally left at repo root to keep compatibility with the original training flow.

## DOWSING source code

```text
src/
  activation_capture.py  forward hooks and token-level model metrics
  bayes_laplace.py       diagonal-Laplace logistic probe
  data_utils.py          byte data helpers, windows, sequence splits
  metrics.py             AUROC/AUPRC/calibration metrics
  nanogpt_loader.py      checkpoint loading without importing train.py
  plotting.py            matplotlib save helper
  probes.py              logistic, ridge, Mahalanobis, standardization
```

`src/` should contain reusable logic. CLI scripts should be thin wrappers around these helpers where possible.

## Experiment scripts

```text
scripts/
  smoke_test.py          quick end-to-end CPU check
  collect_activations.py checkpoint -> metrics.csv + layer arrays
  train_probes.py        train layerwise probes
  eval_probes.py         output-level baselines
  robustness_evals.py    LOSO OOD and ID-only high-loss checks
  make_plots.py          base plots
  analyze_results.py     presentation tables and extra plots
  make_report_tables.py  generated Markdown report
```

These scripts are the runnable pipeline behind the `Makefile`.

## Data

```text
data/uncertainty_byte/
  prepare.py             dataset preparation script
  README.md              generated data notes
  raw/README.md          placeholder for downloaded Tiny Shakespeare
  eval/README.md         placeholder for generated eval bins
```

Generated `.bin`, `meta.pkl`, and `manifest.json` files are ignored by git. Recreate them with:

```bash
make prepare
```

## Config

```text
config/
  train_uncertainty_byte.py
```

This is the main byte-level nanoGPT training config.

## Generated artifacts

```text
artifacts/
  results/       lightweight CSV result tables
  plots/         presentation plots
  activations/   large intermediate activation arrays, ignored
  probes/        serialized probe pickles, ignored
```

The repo keeps final CSVs and plots visible because they make the project inspectable on GitHub. Large intermediate files are ignored. Each artifact subdirectory has a short README explaining whether its contents are tracked or generated.

## Report

```text
report/
  mini_report.md
```

This is generated by:

```bash
make report
```

It is the audited scientific artifact. Keep it more formal than the README.

## Fill-in lab

```text
lab/
  README.md           how to use the fill-in lab
  test.py             milestone test bench
  SOLUTIONS_MAP.md    starter -> reference file map
  checkpoints/        milestone instructions
  starter/            incomplete learner-facing implementation
```

The `lab/starter/` tree mirrors the reference implementation at key learning points and leaves selected functions incomplete. Learners can run:

```bash
python lab/test.py --milestone 1
python lab/test.py --all
```

The tests import from `lab/starter/`, so they do not modify the reference implementation.

## Cloud outputs

```text
modal_outputs/
```

Local Modal downloads are ignored by git. The only tracked file is `modal_outputs/README.md`, which explains how to regenerate full runs.
